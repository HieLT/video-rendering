## REFERENCE PLANNING RULES

### 1. One Reference Equals One Independent Image

Each reference entry represents one independent visual reference image that can be created and stored in the project's Reference Library.

Do not count different details within the same image as separate references.

A single image may show a character together with their clothing, armor, equipment, and signature weapon, provided the composition communicates the intended design clearly.

### 2. Character References

Create a Character Reference when a character needs a stable, recognizable visual identity across scenes.

Consider the following when defining a character reference:

- Face and physical appearance.
- Hair and other distinctive features.
- Body type and silhouette.
- Costume, armor, and clothing.
- Equipment and accessories.
- Signature weapon, when it is normally part of the character's visual identity.

Use a consistent reference name for the same character throughout the film.

If the same character appears in multiple scenes without a meaningful visual redesign, reuse the same reference rather than creating duplicates.

### 3. Character and Signature Weapon: Prefer One Combined Reference

A character's signature weapon should generally be included in that character's Character Reference when both are normally presented together and the weapon's design can be clearly understood.

Do NOT automatically create a separate Prop Reference just because:

- The weapon has a name.
- The weapon is important to the story.
- The character uses the weapon frequently.
- The weapon appears in many scenes.

Create a separate Prop Reference only when there is a distinct production need, such as:

- The object must appear without its owner.
- The scene requires a close-up or detailed design that cannot be communicated adequately in the Character Reference.
- The object is shared, transferred, discovered, or handled independently.
- The object has a visually significant design or state that needs its own reference.
- A separate reference is necessary to maintain consistency across multiple characters or scenes.

When a weapon is already adequately represented in a Character Reference, the Scene → Reference Map must use that Character Reference. Do not invent a separate weapon reference.

### 4. Environment References

Create an Environment Reference when a location or environment has a meaningful and recurring visual identity, or when its visual design is important to generating the scene correctly.

Consider:

- Geography and spatial layout.
- Architecture and structures.
- Terrain and natural features.
- Dominant colors and materials.
- Lighting conditions when they define the location's visual identity.
- Distinctive landmarks and environmental features.

Reuse the same reference for the same location when its identity remains consistent.

Create separate environment references only when locations are visually distinct or when a major environmental transformation requires an independent reference.

Do not create separate references for trivial variations in camera angle, framing, or ordinary lighting.

A location that changes substantially, such as a peaceful village becoming a destroyed and burning settlement, may require a separate state-specific Environment Reference if the change is visually important to the production.

### 5. Prop References

Create a Prop Reference for an important object that requires an independent visual design reference and is not adequately covered by a Character Reference or Environment Reference.

Examples include:

- A significant artifact.
- A distinctive key or emblem.
- A story-critical object handled independently by multiple characters.
- An object whose exact appearance is essential to a reveal or plot point.

Do not create separate Prop References for ordinary background objects, generic equipment, or objects already sufficiently represented in another reference.

Avoid duplicate references for the same physical object.

### 6. Special State References

Create a Special State Reference only when a character or important visual subject undergoes a significant, production-relevant visual transformation.

Examples include:

- A character's distinctly altered or corrupted appearance.
- A clearly different armor or costume state.
- A major transformation caused by magic or another story event.
- A significantly changed weapon state that cannot be adequately communicated by the standard Character Reference.

Do not create a Special State Reference for minor facial expressions, routine poses, temporary movements, camera angles, or ordinary changes in lighting.

If the change can be represented clearly using an existing reference and the scene prompt, do not create another image.

Use names that distinguish the state clearly while preserving the character's identity.

### 7. Reference Naming Rules

Every reference must have one unique, stable, human-readable name.

Follow these rules:

- Use the same exact name everywhere in the output.
- Do not rename the same reference in different scenes.
- Do not create duplicate entries for the same visual identity or asset.
- Distinguish genuinely different characters, locations, objects, or states.
- Use descriptive names that can be matched to actual assets in the project's Reference Library.
- Do not include scene numbers in a reference name unless the reference genuinely represents a unique scene-specific state.
- Do not create multiple names for the same image merely because it serves different purposes.

Reference names are production identifiers. Template 5 must be able to use them exactly as written.

### 8. Reference Image Design Requirements

When describing a planned reference image, prioritize visual clarity, identity consistency, and practical usability for AI video generation.

Reference images should be designed to communicate the intended subject clearly and should not contain:

- Text labels.
- Captions.
- Watermarks.
- Logos.
- Decorative typography.
- Unnecessary graphic overlays.

Do not ask the image-generation stage to place reference names or explanatory text inside the image. Reference names belong in the production data, not inside the artwork.

Do not generate images in this task. Only plan the required references.

### 9. Scene-to-Reference Assignment Rules

Every scene in the supplied approved scene plans must appear in the Scene → Reference Map.

For each scene:

- Assign only references that are genuinely useful for generating that scene.
- Use the exact reference names defined in the Reference List.
- Do not introduce new reference names inside the map.
- Do not assign a reference merely because a character, object, or location is mentioned indirectly.
- Include the relevant character references, environment references, prop references, and special state references as appropriate.
- Use `None` when a category has no required reference.
- Reuse the same reference wherever the same visual identity applies.
- Do not list a separate prop reference if the relevant prop is already adequately depicted in an assigned character reference.
- Do not omit any scene from the approved plans.
- Preserve the original scene numbers and scene names exactly as supplied.

If a scene requires a character in a distinct visual state, assign the appropriate state reference when one has been planned. If no separate state reference is needed, use the standard reference and leave the scene-specific visual details to the video prompt.

### 10. Priority Rules

Assign each reference one priority:

- **MUST CREATE** — Essential for maintaining visual identity or generating a critical scene correctly.
- **RECOMMENDED** — Meaningfully improves consistency or scene quality but is not essential in every circumstance.
- **OPTIONAL** — Provides supplementary visual guidance and can be omitted without substantially affecting production.

Prioritize based on actual production value, not on how often an element is mentioned in the story.

Do not mark every reference as MUST CREATE.

### 11. Missing Visual Decisions

Identify only unresolved visual decisions that materially affect reference creation or scene consistency.

Examples include:

- A character's appearance changes between scenes but the approved story does not establish which design is correct.
- Two descriptions of the same location imply conflicting layouts.
- An important object has inconsistent descriptions.
- A major transformation is mentioned without enough information to establish its visual state.

Do not invent story facts to resolve these conflicts.

Clearly state the unresolved question and identify the affected character, environment, prop, state, or scene.

Do not list minor artistic choices that can reasonably be decided during reference creation.

If no important decisions remain unresolved, output `None`.
